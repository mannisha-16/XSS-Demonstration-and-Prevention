Understanding Cross-Site Scripting (XSS)

Cross-Site Scripting (XSS) is a critical web application security vulnerability that occurs when an application includes untrusted user-supplied data in a web page without proper validation or context-aware output encoding. When the victim's browser parses this unescaped data, it executes attacker-supplied scripts within the trusted security context of the vulnerable website.

Rather than relying on basic browser popup alerts (alert()), this academic project demonstrates the true potential impact of XSS through full-width security alert banners, simulated website defacement, modified dummy announcements, and system status tampering, alongside corresponding Phase 2 defense-in-depth mitigations.

Phase 1: XSS Vulnerability Demonstrations

Controlled Website Impact Simulations

Explore the three distinct execution pipelines and their visual website impact through controlled local simulations:

1. Reflected XSS

Vulnerable

Delivery: HTTP Request Query → Server HTML Stream → Browser Execution.

Untrusted data supplied in a URL query parameter is reflected immediately in the server's HTML response. When triggered, it displays a full-width red banner ("SECURITY ALERT — WEBSITE COMPROMISED") and alters the department notice board heading and system status to "CRITICAL COMPROMISE".

Launch Reflected Demo →

2. Stored XSS

Vulnerable

Delivery: Comment Form → Permanent JSON Storage → Rendered for All Visitors.

The payload is saved permanently in comments.json. Operating on a seamless single-page workflow, submitting a payload triggers the banner ("STORED XSS ATTACK — WEBSITE CONTENT COMPROMISED"), defaces the portal announcement, and persists across page reloads (F5) until reset.

Launch Stored Demo →

3. DOM-Based XSS

Vulnerable

Delivery: Client Parameter → JavaScript Parsing → Unsafe innerHTML Sink.

Client-side JavaScript reads untrusted URL data and inserts it directly into the DOM tree. Executing without any server-side reflection, it triggers the banner ("DOM-BASED XSS — PAGE CONTENT MODIFIED") and modifies the student dashboard elements live in browser memory.

Academic Simulation Safety Constraints

All demonstrations within this project operate strictly within local browser memory and local JSON storage on localhost. In accordance with academic and ethical standards, this project does not perform real credential harvesting, cookie theft, data exfiltration, or external network attacks. All defacement effects are controlled simulations designed for semester project evaluation.
